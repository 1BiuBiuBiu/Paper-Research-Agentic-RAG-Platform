# S3.0.1 Windows 双击启动验收

日期：2026-10-21；应用 0.4.1，基线 ee137ae，分支 fix/windows-launcher。

## 交付与范围

- 用户双击根目录“启动平台.cmd”，调用 scripts/platform.ps1；从项目目录定位既有 .venv，隐藏启动 API 8000 与 Streamlit 8501，分别就绪后打开默认浏览器。关闭成功后的启动窗口不停止服务。
- “停止平台.cmd”核对入口保存的 PID / 创建时间 / 项目解释器与模块，再终止该进程树；复用的原手动服务不擅自接管。
- 端口冲突不关闭占用程序；环境缺失不自动安装；服务启动失败只回收本次创建进程。每项启动等待最多 60 秒，日志保存在忽略的 output/launcher/{apiPort}-{uiPort}/。
- 不改变论文、分类、解析、检索、对话或 UI，无依赖升级、外部模型请求或 schema 迁移。不是独立安装包，依赖既有 .venv。

## 实际验证

系统 Windows，启动执行器为系统 Windows PowerShell 5.1。主机原有服务在隔离测试全程保持正常；测试使用 18000 / 18501、18002 / 18502 等独立端口，RESEARCH_DATA_DIR 指向 tmp/launcher-smoke-data。

| 场景 | 结果 |
| --- | --- |
| 冷启动 API 与页面，启动入口退出 | 两项健康正常，API 返回 0.4.1；入口退出后服务持续可访问 |
| 重复启动 | 成功复用，PID / 创建时间记录与首次完全一致 |
| 停止、重复停止 | 测试端口释放，记录清空；重复停止成功 |
| API 端口为无关 http.server | 明确失败，不关闭该进程，不启动页面 |
| UI 端口为无关 http.server | 明确失败，回收本次新 API，无关服务器存活 |
| 状态记录为无关当前 PID、过期创建时间 | 不终止无关进程 |
| 带空格的隔离目录缺少 .venv | 明确失败，原有 8000 / 8501 服务保持可用 |
| 编码 | PowerShell 源为 UTF-8 BOM，cmd 为 ASCII / CRLF，适配系统 PS 5.1 |
| 根目录实际“启动平台.cmd” | 身份核对后替换本任务此前手动启动的服务；入口正常退出，API 8000 返回 0.4.1、UI 8501 健康、两项 PID 记录齐全。浏览器打开命令成功发出，未另做浏览器视觉核验 |

复现命令形态：

```powershell
$env:RESEARCH_DATA_DIR = 'tmp/launcher-smoke-data'
powershell.exe -NoLogo -NoProfile -File scripts/platform.ps1 -Action Start -ApiPort 18000 -UiPort 18501 -NoBrowser
powershell.exe -NoLogo -NoProfile -File scripts/platform.ps1 -Action Stop -ApiPort 18000 -UiPort 18501
```

初次停止验证失败：端口仍监听。最小诊断确认 PS 5.1 的 ConvertFrom-Json 将 JSON 数组作为一个 System.Object[] 管道项传入，核对函数未逐项读取。改为显式 foreach；完整冷启动 / 重复 / 停止及失败路径重跑通过。验收程序使用文件捕获输出，避免 Windows 后台子进程继承管道句柄让测试工具持续等待 EOF；不将工具等待误报成服务未启动。
