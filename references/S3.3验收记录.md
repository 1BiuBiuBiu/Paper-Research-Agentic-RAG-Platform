# S3.3 批量导入、公式原图与本机密钥配置

日期：2026-10-22（Asia/Shanghai）；应用 0.7.0。当前根目录缺少 `.git`，不能读取原分支 / HEAD、检查 staged diff 或创建原历史上的本地提交；未初始化替代仓库，未推送。

## 已确认范围与实现

用户要求批量上传和解析、拖动上传，随后反馈没有密钥输入窗口。本轮保留逐页阅读和左 PDF 不滚动 / 右解析独立滚动，补充三个可核对行为：

1. 导入使用 Streamlit 原生多文件选择与拖放区域；加入队列后才开始逐项上传 / 解析。单批最多 20 篇 / 200 MiB，每篇仍受 50 MiB / 500 页限制，原单篇 API 独立校验与串行解析锁不变。失败继续、重复内容保留原 ID / 分类，同名不同内容不覆盖。
2. 当前页 formula block 通过原 block_id / 页码找到已保存区域，在对应阅读位置显示原图；无区域保留提取文字，原图读取失败提示对照 PDF。没有运行公式转 LaTeX 模型，没有修改解析记录。
3. 设置 → 服务商 → 选择要配置密钥的服务商 → 打开本机密钥输入窗口。网页只发送服务商 ID；服务端验证该服务商的密钥变量名，启动 Windows 密码式窗口。另提供根目录“配置模型密钥.cmd”设置内置 DeepSeek。

密钥只从本机窗口经重定向 stdin 传给本机 helper，更新服务端 `.env` 的一个变量；其他配置保留，取消不写文件。没有 Key HTTP 输入字段、浏览器状态或命令行 Key 参数，不回填旧值，stdout / stderr 不回传。窗口单实例互斥。保存后要求任务结束再手动停止 / 启动平台，避免自动重启打断批量解析；进程环境变量优先级不变。

## 队列边界

- 会话内保存队列，普通组件 rerun 不自动重复请求；手动继续只处理 waiting / failed / error。服务器接管原件后释放该项会话内 bytes。
- 有原文档 ID 的失败项先检查状态，失败才调用原 ID 的 retry；仍在解析则提示稍后确认，不另起解析。丢失成功响应后重交原内容，依赖服务端 SHA256 去重，不生成新文档。
- 某篇无效 / API 错误不会阻断后续。清空队列不请求删除论文。队列不是后台持久任务，关闭 / 刷新后的未提交内容不承诺恢复；已入库记录继续持久保存。
- 不自动重试外部模型，不新增付费请求或论文外传。Key 保存并不代表供应商鉴权 / 生成已验证。
