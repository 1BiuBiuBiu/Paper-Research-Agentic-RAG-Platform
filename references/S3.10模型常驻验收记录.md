# S3.10 本地模型常驻与空闲释放验收记录

日期：2026-10-24（Asia/Shanghai）
应用版本：0.13.8

## 1. 用户确认范围

用户确认采用“常驻独立 Docling / BGE / 精排 worker + 空闲超时释放”。目标是同一批解析、连续建索引和连续问答不重复加载本地模型；不使用模型时释放 CPU 内存及未来 XPU 共享显存。本轮不启用 GPU、不增加多 API worker、不并行解析论文，也不改变模型、解析质量规则、索引格式或检索算法。

批量导入页面仍逐篇调用单文档接口，服务端没有可靠的“批次结束”事件；页面也可能断开。因此释放条件采用队列空闲 TTL，而不是信任客户端结束信号。

## 2. 实现与边界

- 新增通用 `PersistentWorker`：首次任务启动隔离子进程，stdin 发送单行 JSON 命令；结果通过原子响应文件确认，避免 Docling/Transformers 的 stdout 干扰协议。
- Docling worker 首次任务创建一个 `DocumentConverter`，后续 PDF 复用；BGE-M3 与 Cross-Encoder 分别缓存一个固定模型实例。三个 worker 相互隔离且各自串行。
- 正常完成后启动空闲计时：Docling 120 秒、BGE-M3 300 秒、Cross-Encoder 300 秒。新任务取消当前计时；环境变量 `RESEARCH_DOCLING_IDLE_SECONDS`、`RESEARCH_EMBEDDING_IDLE_SECONDS`、`RESEARCH_RERANKER_IDLE_SECONDS` 可覆盖。
- 原硬超时保持：Docling 300 秒、BGE 600 秒、精排 120 秒。超时、管道断开、非法响应或 API lifespan 退出时终止对应进程；下一任务重新加载，不对失败任务静默重试。
- worker 环境继续剔除名称含 `API_KEY / MODEL_KEY / SECRET / TOKEN` 的变量；BGE/精排保持 Hugging Face 离线及禁遥测。论文正文不写日志或响应协议。
- 内存释放以终止子进程为准，不依赖 `del model` 或设备缓存 API。父进程崩溃/关闭 stdin 时 worker 命令循环也会退出。

## 3. 本机复用证据

在 Windows 11、Python 3.12.7、Torch CPU 环境运行；输入为仓库自建 3 页 PDF 与合成短文本，不读取用户论文、不调用远程或付费服务。以下为单次烟测，不作为正式容量/吞吐基准：

| worker | 第一次（含进程/模型冷加载） | 同进程第二次 | 复用检查 |
| --- | ---: | ---: | --- |
| Docling，自建 3 页夹具 | 13.743 s | 1.919 s | PID 相同，均返回 3 页 |
| BGE-M3，单句编码 | 9.960 s | 0.105 s | PID 相同 |
| MiniLM Cross-Encoder，10 对文本 | 8.673 s | 0.058 s | PID 相同 |

`tests/test_model_worker.py` 另以短 TTL 验证：连续请求复用同一 PID/递增进程内计数；空闲后 PID 消失，下一请求启动新 PID且计数重置；硬超时后 PID 立即消失；API 退出会调用解析、embedding、精排三个组件的 `close()`。

## 5. 限制

- 这是消除重复冷加载的生命周期修订，不代表 Intel XPU 已启用；当前 embedding、精排和 Docling 的 Torch 仍走 CPU。
- 同类 worker 仍一次只处理一个任务；批量吞吐来自复用模型，不来自多进程并行。
- Docling 与后台 BGE 索引在不同 worker 中，若上传下一篇时上一篇正建索引，两者仍可能同时占用内存；空闲 TTL 只保证最终释放，不是全局内存调度器。
- 未运行用户论文批量性能测试、GPU A/B、远程模型、Tavily、UI 视觉验收或千篇容量测试。
