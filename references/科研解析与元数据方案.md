# 科研 PDF 解析、元数据与图片方案

更新：2026-10-20。S0 已安装并验证 Docling 2.140.0 的解析/清洗/图注/预览；外部元数据、自动 JIF、VLM 与联网问答仍为后续计划。实测证据见 [S0 验收记录](S0验收记录.md)。

## 官方能力依据与选型边界

候选 Docling 的统一文档结构可表达正文与页眉页脚、块坐标、结构顺序及来源，并支持图片导出。这些是优先验证它的依据，不能由文档能力直接推断对所有双栏论文解析正确。来源：[文档结构](https://docling-project.github.io/docling/concepts/docling_document/)、[图导出示例](https://docling-project.github.io/docling/_generated/examples/export_figures/)、[项目说明](https://github.com/docling-project/docling)。元数据匹配仍需独立模块，不能假设版面解析器会可靠生成全部学术字段。

需先验证：Windows/Python 兼容、依赖与模型下载大小、CPU/RAM 需求、冷启动/单篇耗时、双栏样本、图区域与坐标映射。硬件尚未知，故保留解析器接口；若更换候选需记录测量依据和影响，不能静默替换。

## 文字与清洗

1. 保存原 PDF；提取页尺寸、旋转、文本块/字体、块类型及 bbox。明确坐标原点与单位，渲染/引用统一转换。
2. 按布局恢复阅读顺序：跨栏标题/摘要/图表先分区，再按栏取块；不能简单全页按 y 排序造成逐行串栏，也不能假设每页始终双栏。
3. 区分 furniture 与正文；页眉/页脚额外参考跨页重复、位置、字体及页码变化。只做有证据的噪声排除，不能固定裁掉顶部/底部若干百分比。
4. 本文标题、作者/单位、有效脚注、图注、公式编号与参考文献须按类型保留；参考文献可单独索引，不能当页脚删光。先从标题区/页眉等提取出版信息，再将重复噪声排除正文。
5. 保存 raw_text/clean_text、原页、bbox、排除原因、parser_version；清洗预览可回看。英文断行连字符等规范化保留映射，避免损坏 DOI、负号和专业术语。
6. 按章节/段落/图注结构分块，再做长度限制；跨页片段保留全部来源，不伪造为单页。

验收基于有金标准的夹具与真实论文逐页抽查：已知块顺序、预期排除项、关键保留文本及坐标。真实解析失败须公开质量状态，不能用字符串拼接替身通过后宣称版面问题解决。

## 论文元数据

字段：title、authors、publication_year、doi、venue_type、journal/conference_name、ISSN、volume、issue、pages/article_number、abstract、publisher（可得时）。会议名与论文集名可同时保留；预印本与正式版本记录关联但不自动覆盖成同一版本。

来源顺序：PDF 内嵌/XMP 与首页/出版区证据 → DOI 精确查元数据 → 无 DOI 时题名/作者/年份候选匹配 → 用户确认/人工修订。PDF 内嵌元数据可能是模板残留，必须与页面交叉检查；参考文献里的 DOI 不自动当作本文 DOI。低置信度、多个同名候选与冲突保留可见状态，不自动选择第一条。

Crossref 提供学术书目元数据 API，可按 DOI 获取记录；使用其字段补全仍需校对和缓存/超时/限流处理，不能保证每篇均有完整记录。[Crossref 官方 API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)。数据外发仅发送 DOI 或必要题名/作者，不默认上传 PDF。

字段保留原始提取值、当前值、来源/原文位置或 URL、抓取时间、匹配状态及人工覆盖。人工修订优先，刷新外部信息只能提出新候选。

## 期刊影响因子

JIF 按期刊与指标年份存储，不是论文属性，也不等同引用次数。Clarivate 的 Journals API 提供 JCR 期刊指标，官方 API 需要付费访问；当前没有确认用户具备该数据源。[Clarivate 官方 API 与接入条件](https://developer.clarivate.com/apis/wos-journal)。

实现数据源适配器与导入/手工录入入口，不默认购买任何服务。至少存 metric_name=JIF、期刊标识（优先 ISSN）、metric_year、value、source、retrieved_at，并标明人工/导入/API 来源。论文发表年份与指标年份分别显示；不能把较新指标回填成论文发表当年指标。

状态区分：已获取、未获取、来源不可用、不适用。会议/预印本通常展示不适用；缺失不能显示 0，也不能让大模型猜值。将来如加入分区/会议等级，要分别标明机构/版本/学科类别，不能与 JIF 混为一个字段。

## 图片与图文证据

- 提取层：图区域、figure_id、图号、bbox、物理页、清晰度状态。位图可提原资产；矢量/多对象图按版面区域渲染，不能仅枚举 PDF 嵌入图片而漏图。logo/装饰与内容图分开。
- 关联层：图注、正文中的 Figure/Fig./图号引用、所属章节；多面板尽量保留整图与面板关系，不凭近邻把跨栏图注配错。
- 索引层：先检索图注及相邻/引用正文，指向实际图块；文字证据与视觉输出分别记录。
- 按需视觉层：问题涉及图，且已配置支持图片的模型时，只发送选中论文内必要图块与图注；保存 OCR/解读类型、模型和时间。图注检索和真实像素分析在 UI 明确区分。
- 证据层：展示原图、图注、页码和所用区域；模型说“上升趋势”等解读应可核查。精确数值需来自可读标签或原文/表格，不能从模糊曲线捏造数据。

S0 交付提取/关联/预览；VLM 问答在 S4 单独验收。全面 OCR、公式识别和所有图表数据自动重建不作为当前解析完成的前提。

## 联网补充与论文范围的关系

默认流程：所选论文摘要定位 → 正文/图注混合检索 → 重排/相关性判断 → 最多两次查询改写（候选初始值） → 仍不足时搜索互联网 → 明确区分两类证据后作答。仅本地开关关闭所有搜索请求；配置缺失、限流、超时和无结果分别反馈。

网页证据不自动写进用户论文库，也不使本地检索从 A 扩展至未选的 B。网页内容若补充/纠正本地论文，应注明冲突与来源，不能把网页说法归于论文。记录搜索查询、URL、标题、获取时间及实际读取的片段类型；只有搜索摘要时不能宣称读取网页全文。模型/搜索次数与耗时有界；原上游的联网能力完整迁移，但错误处理和来源追踪需加强。
