## 口径与判定

- **标题**：同文档同页一对一匹配，阈值 0.90（项目冻结协议）；gold 为 `evaluation/datasets/v0.2/structure_gold.jsonl` 中五篇的 279 个候选（已排除 `needs_review`），预测为当前标题规则作用在既有 Docling 解析结果上。误报 22 = 未被匹配的系统预测。Macro F1 按篇平均另列，与 micro F1 用途不同。
- **检索**：按 README 采集“原始问题第一轮精排后、LLM 过滤前 Top 5”。中文题的精排问句使用 S3.9 记录的实际英译（不重新调用模型）。`relevance=2` 仅给命中直接金标准的行，`1` 给同页相关但不含金标准的行，`0` 为无关。`ideal_relevances` = 全部直接金标准 + 本轮相关（1 级）证据。
  - 因为所有题的金标准都标注为非穷尽，**Recall@5 没有合法分母，返回 null**；报告 Hit@5 与 nDCG@5，不把 Hit 冒充 Recall。
- **回答**：沿用 S3.7.4 语义完整性口径（接受等价表达；数值、单位、数据集、比较条件错误仍判失败）。`Grounded Answer Success` 由代码推导：答案正确 ∧ 必要信息完整 ∧ 引用支持 ∧ 无越界 ∧（应拒答题正确拒答）∧（可回答题有引用且逐条支持）。
- **引用**：逐条核对“该引用文本是否包含答案归给它的数值/结论”。本轮 57 条全部通过（表格行与引用段落已在生成前合并，数值与主张位于同一条证据）。
- **标注者**：本助手按上述口径单次复核，未做双人盲审；因此这些数字是“单评审标注”的成绩，不是双人仲裁结果。

## Recall@5 的两种口径

协议口径（金标准标注为非穷尽）只报 Hit@5；按用户要求把“当前金标准视为完整”后再算 Recall@5，两种都列：

| 口径 | 值 | 分母 / 明细 |
| --- | --- | --- |
| 协议：Recall@5 | **null** | 22 题金标准均非穷尽，按 README 不计算 |
| 协议：Hit@5 | 0.8636（19/22） | 22 题 |
| 视金标准为完整：**Recall@5（macro）** | **0.8371（18.42/22）** | 官方评分器 `recall_at_5`，22 题 |
| 视金标准为完整：Recall@5（micro） | **0.7805（32/41）** | 41 条直接金标准，Top 5 命中 32 条 |

逐题未命中：`ADD-CMIR-001`（2 条金标准，0 命中）、`ADD-PS-001`（1 条，0）、`ADD-PS-004`（4 条，0）；部分命中：`ADD-CMIR-004` 2/3、`ADD-MAM-002` 3/4。

解释：这 3 道零命中的题，金标准落在首轮 Top 5 之外（生产流程用 Top 10 进账本，`ADD-CMIR-001`、`ADD-PS-001` 最终仍答对；`ADD-PS-004` 另有表注冲突）。同一批题按 4.1 节的 k=10 sweep，全部金标准进入 Top 10，因此 Recall@5 的缺口来自 Top 5 截断，不是召回池缺失。

注意：金标准被标注为非穷尽，所以“Recall@5=83.71%”只是**对当前金标准子集的召回**，不是对论文全部相关证据的召回；引用时应写明这一前提，不能与协议 Hit@5 混报。
