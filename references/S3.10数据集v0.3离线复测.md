# 数据集 v0.3 离线复测（免费，无 LLM）

- 日期：2026-10-24；应用版本 **0.13.8**（本轮只改评估脚本，未改应用行为）；在 Git `dc31adb` 之上运行。
- 数据集：`evaluation/datasets/v0.3`（`expanded_v0.5_project_aligned`，人工金标准草稿，被 `.gitignore` 排除）。
- **0 次付费调用、0 次联网、0 次模型切换**：只用本机 Docling 布局解析、BGE-M3 向量、BM25 与 Cross-Encoder。
- 结果目录：`output/evaluation/dataset-v0.3-0.13.8`（`manifest.json` 记录输入 SHA256、解析来源与耗时）。

## 1. 为什么这一轮只能给标题与检索

新数据集只有标注，没有系统输出；协议要求先冻结金标准再跑系统。因此本轮只跑可离线复现的两组指标：

| 指标 | 本轮状态 |
|---|---|
| Heading F1、Level Accuracy | 已测（第 4 节） |
| 混合召回 Hit@5 / Hit@10 / Hit@20、nDCG | 已测（第 5 节） |
| Recall@k | **不发布**：所有可答题 `direct_evidence_exhaustive=false` |
| Grounded Answer Success、Citation Precision、Scope Leakage | **null / not evaluated**：需要授权的付费端到端运行 |

协议第 2.2 节的“Recall@5 发布前提”明确禁止把 Hit@k 冒名为 Recall@k。本报告所有命中比例都写作 **Hit@k**，`metrics.json` 里 `recall_at_k` 保持 `null`。

## 3. 运行方式与输入核验

```
uv run python -m evaluation.replay_dataset --dataset evaluation/datasets/v0.3 \
  --out output/evaluation/dataset-v0.3-0.13.8 \
  --cache output/evaluation/pilot-2026-10-23 \
  --cache output/evaluation/expanded-v0.3-0.11.2 \
  --cache tmp/v03-parse-cache
```

- 10/10 篇 PDF 的 SHA256 与 `dataset_summary.json` 一致；`2602.16197v3(1).pdf` 实际保存为 `~/Downloads/2602.16197v3.pdf`（浏览器重复下载后缀），脚本按去重后的文件名重试并通过指纹校验。
- 10/10 篇复用已记录的解析结果（`result.json` 的 SHA256 写入 `manifest.json`），本轮没有重新解析 PDF。
  - 7 篇复用 2026-10-23 的解析；3 篇新论文的 Docling 解析在本轮**第一次尝试**中完成——该次运行被沙箱拒绝临时目录清理（`WinError 5`）而中断，重跑按 SHA256 复用，并把结果复制进本次运行目录（复制后 SHA256 不变，`manifest.json` 的 `parse_origin` 标为 `docling_parsed_this_session_then_reused`）。
- 索引：**10 篇 / 2,985 chunks**（chunks v5，段落优先切分），RRF 候选 **60** → Cross-Encoder 精排窗口重放 **top 20**；生产窗口仍是 10（`RESEARCH_RERANK_TOP_N`）。
- 总耗时 **866.4 秒**，其中建索引 **775.7 秒**（CPU，BGE-M3）。打分与装配逻辑在 `evaluation/replay_scoring.py`（纯函数）；拆分后重跑一次，`benchmark.json` / `coverage.json` / `metrics.json` / `heading_report.json` 与拆分前逐字节一致，只有耗时和 Git commit 不同。

### 5.1 6 道题在池内但没进窗口

`ADD-MOD-005`、`ADD-WIS-004`、`ADD-WIS-005`、`ADD-ATTN-004`、`ADD-BLIP-002`、`ADD-BLIP-004`：金标准在融合池的名次分别是 11 / 7 / 1 / 2 / 2 / 1，但精排 top 20 里没有。这不是召回缺失，而是**精排排序**。

**原因是查询语言**：本数据集 51 道题全部是中文，而生产链路在精排前会用一次 LLM 把中文问题译成英文（该次调用不计入 3 次上限）。离线重放不能调用 LLM，只能用原中文问句精排。对上述 6 题做定向诊断（助手手写英文问句重放，仅诊断、不计入指标）：

| 题号 | 中文问句首次命中 | 英文问句首次命中 | 英文问句覆盖金标准 |
|---|---:|---:|---:|
| `ADD-MOD-005` | 无（>20） | **1** | 2/2 |
| `ADD-WIS-004` | 无（>20） | **1** | 1/1 |
| `ADD-WIS-005` | 无（>20） | **1** | 1/1 |
| `ADD-ATTN-004` | 无（>20） | **1** | 2/2 |
| `ADD-BLIP-002` | 无（>20） | **1** | 3/3 |
| `ADD-BLIP-004` | 无（>20） | **1** | 3/3 |

6/6 命中且全部金标准回到第 1 名。这是**定向诊断，不是总体指标**：6 题是“已经失败”的题，不代表英译能把全部题都提到第 1。

## 6. 口径与限制

- **Hit@k ≠ Recall@k**：金标准非穷尽（`direct_evidence_exhaustive=false`），`recall_at_k` 保持 null。
- **金标准匹配是自动文本匹配**（同篇 + 同页 + 数值/前三个长词），不是人工逐条判定。表格行被解析器合并、图注被拆到不同 chunk 时可能漏判，因此上面的命中数偏保守；反过来，数值偶然出现在同页其他片段时也可能宽松。
- **精排用中文问句**，生产路径先英译；5.1 的诊断只覆盖 6 道已知失败题。
- **7 道不可答题**（无直接金标准）按协议不进入检索指标；它们只影响将来的拒答评价。
- **4 条待复核候选**（WisdoM 附录目录页、CMIR 数学花体标题等）按协议单独排除，未计入标题分母；裁决前标题分数不能当作冻结金标结果。
- **回答与引用指标为空**：没有授权的付费运行就没有系统回答，协议禁止填写占位值。
- 标注为**助手单次复核**，不是双人盲审；本轮只跑系统侧，未改任何金标准。
